React Query se encarga de coordinar consultas, caché, carga y errores para que no tengas que reconstruir esa infraestructura en cada componente.

## Prepara un QueryClient estable

Crea un `QueryClient` y distribúyelo mediante `QueryClientProvider`. No lo recrees en cada render: perderías la caché que pretendes compartir.

```tsx
import { QueryClient, QueryClientProvider, useQuery } from '@tanstack/react-query'

const queryClient = new QueryClient()

function Root() {
  return <QueryClientProvider client={queryClient}><App /></QueryClientProvider>
}

function useComments() {
  return useQuery({ queryKey: ['comments'], queryFn: getComments })
}
```

La `queryKey` identifica el resultado. Si la consulta cambia según un filtro, ese filtro debe formar parte de la clave. Dos componentes que leen la misma consulta pueden compartir datos sin pasarse el resultado por props.

## Paginación e infinite queries

Una consulta infinita mantiene una colección de páginas. `pageParam` indica cuál pedir y `getNextPageParam` decide si existe otra. Conviene devolver desde el servicio tanto los usuarios como el siguiente cursor.

```tsx
const query = useInfiniteQuery({
  queryKey: ['users'],
  queryFn: ({ pageParam = 1 }) => fetchUsers({ pageParam }),
  getNextPageParam: lastPage => lastPage.nextCursor
})

const users = query.data?.pages.flatMap(page => page.users) ?? []
```

Empieza con un botón «Cargar más». Desactívalo si ya hay una carga en curso o no quedan páginas. Después puedes añadir `IntersectionObserver` para solicitar la siguiente cuando un marcador entra en pantalla. Limpia el observer al desmontar y evita disparar peticiones duplicadas.

## Cuándo refrescar los datos

La caché no significa que el resultado sea válido para siempre. Decide cuánto tiempo puede considerarse reciente, cuándo actualizarlo y qué debe ocurrir al volver a la pestaña. El vídeo explora refetching y DevTools para observar esas decisiones.

No confundas `isLoading` con cualquier actividad de red. Puedes tener datos visibles y estar refrescándolos en segundo plano. Enseñar un pequeño indicador evita desmontar toda la lista cada vez que se consulta otra vez.

## Una mutación cambia datos

Una query lee; una mutación expresa una operación como crear un comentario. Cuando termina puedes invalidar la consulta para volver a pedirla o actualizar la caché con el resultado confirmado por el servicio.

```tsx
const mutation = useMutation({
  mutationFn: postComment,
  onSuccess: () => queryClient.invalidateQueries({ queryKey: ['comments'] })
})
```

Desactiva el envío mientras está pendiente, conserva el texto si hay un error y ofrece reintento. No muestres éxito antes de saber qué significa ese éxito en tu aplicación.

## Implementa el rollback

La clase termina explicando por qué no basta con insertar un comentario en pantalla. Si el servicio lo rechaza, hay que eliminar ese resultado provisional y recuperar un estado coherente.

```tsx
useMutation({
  mutationFn: postComment,
  onMutate: async comment => {
    await queryClient.cancelQueries({ queryKey: ['comments'] })
    const previous = queryClient.getQueryData(['comments'])
    queryClient.setQueryData(['comments'], (old = []) => [
      ...old, { ...comment, id: crypto.randomUUID(), preview: true }
    ])
    return { previous }
  },
  onError: (_error, _comment, context) => {
    queryClient.setQueryData(['comments'], context?.previous)
  },
  onSettled: () => queryClient.invalidateQueries({ queryKey: ['comments'] })
})
```

El fragmento ilustra el flujo; en TypeScript tipa también la colección, las variables de la mutación y su contexto. Si permites varias mutaciones simultáneas, una instantánea global puede sobrescribir otros cambios: considera IDs provisionales y rollback por operación.
