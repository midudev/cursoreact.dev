## Estado, acciones y reducers

Redux centraliza un estado que varios componentes pueden consultar. Una acción describe qué ha ocurrido; un reducer calcula cómo cambia la store. Redux Toolkit reduce la configuración con `configureStore` y `createSlice`.

```typescript
import { configureStore, createSlice, type PayloadAction } from '@reduxjs/toolkit'

type User = { id: string; name: string; email: string; github: string }
const initialState: User[] = []

const usersSlice = createSlice({
  name: 'users',
  initialState,
  reducers: {
    addUser(state, action: PayloadAction<User>) {
      state.push(action.payload)
    },
    deleteUser(state, action: PayloadAction<User['id']>) {
      return state.filter(user => user.id !== action.payload)
    }
  }
})

export const store = configureStore({ reducer: { users: usersSlice.reducer } })
export const { addUser, deleteUser } = usersSlice.actions
```

Los reducers de `createSlice` trabajan sobre un borrador gestionado por Immer. Por eso `push` resulta válido dentro de ese contexto. No generalices esa sintaxis a cualquier objeto de estado de React: fuera de Immer debes conservar la inmutabilidad por tu cuenta.

## Conecta la store a React

Coloca `Provider` por encima del árbol que consume Redux. Deriva los tipos de la propia store para que no se desincronicen cuando añadas reducers.

```tsx
export type RootState = ReturnType<typeof store.getState>
export type AppDispatch = typeof store.dispatch

export const useAppDispatch: () => AppDispatch = useDispatch
export const useAppSelector: TypedUseSelectorHook<RootState> = useSelector

function UsersTable() {
  const users = useAppSelector(state => state.users)
  const dispatch = useAppDispatch()
  return <tbody>{users.map(user => (
    <tr key={user.id}>
      <td>{user.name}</td><td>{user.email}</td>
      <td><button onClick={() => dispatch(deleteUser(user.id))}>Eliminar</button></td>
    </tr>
  ))}</tbody>
}
```

En este fragmento, `TypedUseSelectorHook`, `useSelector` y `useDispatch` se importan desde `react-redux`. El vídeo extrae estos hooks para que los componentes no repitan detalles de tipado.

## Crear y validar usuarios

El formulario recoge nombre, correo y usuario de GitHub. Valida los campos, elimina espacios y genera un ID estable antes de enviar la acción. Una validación fallida es estado local del formulario: no hace falta subir cada mensaje de error a Redux.

## Persistencia con middleware

Un middleware rodea el procesamiento de una acción. Para persistir, deja primero que la acción llegue al reducer mediante `next(action)` y después consulta el estado actualizado con `store.getState()`. Guardar antes de `next` persistiría el valor anterior.

```typescript
const persistenceMiddleware: Middleware = store => next => action => {
  const result = next(action)
  localStorage.setItem('curso-users', JSON.stringify(store.getState()))
  return result
}
```

Este ejemplo es deliberadamente pequeño. En producción, filtra las acciones relevantes, valida los datos recuperados y contempla errores de almacenamiento. No introduzcas peticiones HTTP ni acceso al DOM dentro del reducer.

## Rollback y práctica

Para deshacer una eliminación necesitas conservar el usuario anterior. Si el servicio falla, una acción de rollback puede restaurarlo. Si además quieres mantener el orden original, guarda su posición. El rollback forma parte de la operación: una notificación de error sin restaurar los datos deja una interfaz incorrecta.
