## useCallback

El hook `useCallback` te permite memorizar funciones para evitar recreaciones innecesarias en cada render.

```jsx
import { useCallback } from 'react'

function MyComponent({ onItemClick }) {
  const handleClick = useCallback((id) => {
    onItemClick(id)
  }, [onItemClick])

  return (
    <button onClick={() => handleClick(1)}>
      Click me
    </button>
  )
}
```

## useMemo

El hook `useMemo` te permite memorizar valores computados costosos.

```jsx
import { useMemo } from 'react'

function ExpensiveComponent({ items }) {
  const sortedItems = useMemo(() => {
    return [...items].sort((a, b) => a.name.localeCompare(b.name))
  }, [items])

  return (
    <ul>
      {sortedItems.map(item => (
        <li key={item.id}>{item.name}</li>
      ))}
    </ul>
  )
}
```

## useRef

El hook `useRef` te permite crear referencias mutables que persisten entre renders.

```jsx
import { useRef, useEffect } from 'react'

function FocusInput() {
  const inputRef = useRef(null)

  useEffect(() => {
    inputRef.current?.focus()
  }, [])

  return <input ref={inputRef} type="text" />
}
```

La memoización añade complejidad. Primero identifica el problema de rendimiento y comprueba que la optimización tenga efecto.

## Cuándo usar cada uno

- **useCallback**: Cuando pasas funciones como props a componentes hijos que usan `React.memo`
- **useMemo**: Para cálculos costosos que no necesitan recalcularse en cada render
- **useRef**: Para acceder directamente a elementos del DOM o mantener valores que no causan re-renders

Estos hooks son fundamentales para optimizar el rendimiento de aplicaciones React complejas.
## El proyecto del vídeo: un buscador de películas

El hilo conductor de la clase es una prueba técnica: crear un buscador con formulario, resultados en cuadrícula y ordenación. Los hooks aparecen cuando resuelven una necesidad concreta. Abre el [buscador integrado](/demos/05-react-buscador-peliculas/) y busca una película antes de seguir los pasos.

Empieza con una respuesta de ejemplo para construir la interfaz sin depender de la red. Después mueve la consulta a un servicio. El componente debería trabajar con películas que tengan los campos que necesita, no con todos los nombres y convenciones de OMDb.

```javascript
export async function searchMovies(search) {
  const params = new URLSearchParams({ s: search, apikey: PUBLIC_DEMO_KEY })
  const response = await fetch(`https://www.omdbapi.com/?${params}`)
  if (!response.ok) throw new Error('No se pudieron buscar películas')
  const data = await response.json()
  if (data.Response === 'False') return []
  return (data.Search ?? []).map(movie => ({
    id: movie.imdbID,
    title: movie.Title,
    year: movie.Year,
    poster: movie.Poster
  }))
}
```

`PUBLIC_DEMO_KEY` representa una clave pública permitida para el ejemplo, no una clave privada que debas incrustar en el cliente. Mantener esta traducción junto al servicio evita que un cambio de contrato de la API se propague a todos los componentes.

## Formularios: estado controlado y FormData

Un input controlado guarda el texto en React y permite validarlo mientras escribes. Si solo necesitas los datos al enviar, `FormData` permite leer todos los campos con nombre sin crear una referencia para cada uno.

```jsx
function SearchForm({ onSearch }) {
  function handleSubmit(event) {
    event.preventDefault()
    const data = new FormData(event.currentTarget)
    const search = String(data.get('search') || '').trim()
    if (search.length < 3) return
    onSearch(search)
  }
  return <form onSubmit={handleSubmit}>
    <label htmlFor="movie-search">Película</label>
    <input id="movie-search" name="search" required minLength={3} />
    <button>Buscar</button>
  </form>
}
```

No consultes el DOM con `document.querySelector` cada vez que necesitas un valor. Escoge una de estas estrategias según la interacción. El vídeo compara refs y formularios controlados para mostrar qué información necesita provocar un render.

## Evita repetir la misma búsqueda con useRef

Una referencia recuerda un valor sin renderizar al cambiar. Puedes guardar la última consulta para descartar envíos repetidos. Actualiza esa referencia en el momento adecuado: si la petición falla y quieres permitir reintento, no bloquees para siempre el mismo texto.

```jsx
const lastSearch = useRef(null)

const getMovies = useCallback(async search => {
  if (lastSearch.current === search) return
  lastSearch.current = search
  try {
    const nextMovies = await searchMovies(search)
    setMovies(nextMovies)
  } catch (error) {
    lastSearch.current = null
    setError(error.message)
  }
}, [])
```

El fragmento omite la carga para centrarse en la referencia. Una versión completa representa carga y error y resuelve respuestas fuera de orden. `useCallback` conserva la identidad de la función; no evita que su cuerpo se ejecute cuando la llamas.

## Ordenar resultados y usar debounce

La ordenación es un valor derivado. Usa una copia antes de `sort` y conserva el cálculo con `useMemo` cuando tenga sentido. El criterio y las películas son dependencias del resultado. No uses un array vacío para silenciar que el cálculo depende de datos que cambian.

Si buscas al escribir, el debounce espera una pausa antes de consultar. Una implementación creada de nuevo en cada render pierde su temporizador anterior: conserva su identidad y cancela el trabajo pendiente al desmontar. La clase termina construyendo esta idea paso a paso.

<LessonNote title="Conservar una referencia no significa congelar los datos" tone="warning">
Una función memoizada utiliza los valores del render que la creó. Si lee una prop o un estado, inclúyelo en sus dependencias o pásalo como argumento. Omitir dependencias puede dejar una función trabajando con datos antiguos.
</LessonNote>
